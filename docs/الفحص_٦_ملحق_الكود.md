# «أنشودتي» code review (round 6, code side)

Reviewer stance: first look at the code, adversarial. Repo at `89a72a4`, read-only. Everything was built and run from a copy at `review6/code/repo`, served on port 8771. Probe scripts: `review6/code/probe1.py`, `probe2.py`, `probe3.py`.

**Baseline:** `python3 build.py` passes: 39 poems, 498 KB `www/index.html` (no fonts embedded locally), 236 pictures (11 MB) in `www/img`, and a 15.3 MB `dist/أنشودتي.html`. All six Chromium e2e suites pass with 0 failures: e2e 153 s, features 134 s, data, fixes, decisions, lesson. No XSS fired in a hostile-input sweep (details in "checked and fine").

## HIGH

### H1. Memorisation state is stored as segment *indices*, and the segments change with the child's age. Progress silently changes meaning, including false "memorised whole poem" badges.
- **Evidence:** `segSize`/`segments` (src/template.html:463-465) depend on `kidAge(k)`. `mem`, `pend`, `rpend`, `rev`, `echoOk`, `seg` and each recording's `seg` all store indices into that age-dependent list (lines 474, 479, 818-831, 1428-1442, 1398). The "whole poem" index is `segs.length`, so it moves too.
- **Repro (probe1.py, case 1).** Poem «٦» has 12 verses. At age 7 the segments are `[[0,3],[3,6],[6,9],[9,12]]` and "whole" is index 4. At age 8 they are `[[0,4],[4,8],[8,12]]` and "whole" is index 3.
  - At age 7, set `mem=[3]` (only the last quarter memorised): `badges().mem` is `false`.
  - Change the age to 8: `badges().mem` becomes `true`. The poem now shows 🧠, the certificate button and the album sticker.
  - `segName({seg:3})` now reads «النشيد كله متصلاً».
- **Impact:** This hits every family once a year, since children have birthdays. It also hits as soon as a parent corrects an age in «العمر و👦/👧». Stamps, reviews, weak-verse ranges and the queue labels then point at the wrong verses. The same mismatch already happens today in two other places:
  - A take saved under a different `who` (the name field in the save sheet) gets `recSeg` from the *current* kid's segmentation (line 789/818), but is stored for another kid whose age may differ.
  - `stampEffects` recomputes `segments(p,r.who)` at stamp time (line 1430), not at record time.
- **Fix:**
  1. Store verse ranges, not indices: `mem:[[a,b],...]`, `rev:{"a-b":...}`, and `r.range=[rA,rB]` on each take (already known at line 789).
  2. Derive badges by coverage. The poem is memorised when the union of stamped ranges covers `[0,n)`, or the whole-range take was stamped.
  3. Migrate old indices using the segmentation that was in force. Failing that, freeze a per-kid `segSize` at first use and never recompute it.

### H2. Pack matching is greedy, so one typo can give verses the *wrong* meaning and drop the following ones.
- **Evidence:** `packMap` (line 389). For each typed verse it takes the **first** later key that hits and advances `j` past it. It never backtracks, and it has no alignment score.
- **Repro (probe2.py, «greedy»).** «وصية لاجئ» is typed from its keys, all aligned `[0..7]`. Then line 1 alone is changed to a typo plus a word from pack line 6: `['الغصق يا ولدي','تذكر الدار']`. The map becomes `[5,null,null,null,null,null,6,7]`:
  - Line 1 now shows pack line 6's meaning, its «ما معنى البيت؟» answer and possibly its picture.
  - Lines 2-6 lose everything.
- **Impact:** The child sees a confident but wrong explanation. The design comment at line 380 says "a typo costs only that verse", and that is false.
- **Fix:**
  1. Replace the greedy scan with an LCS/DP alignment: score = key hits, monotone mapping, with skips allowed on both sides.
  2. Accept a mapped verse only if it hits at least one key and is not better explained by its neighbour.
  3. Add a test with a typo line that contains a later key word.

### H3. A different poem that merely shares a pack's title adopts the pack at 50% hits.
- **Evidence:** line 391-392. `titled` lowers the threshold to `max(3, ceil(n*0.5))`. For «فلسطين داري» (8 keys) that is 4 hits, and the keys include `فلسطين` (twice), `بلاد`, `شعب`, `مهد/جد`, which are words in almost any patriotic children's poem.
- **Repro (probe2.py).** A made-up 5-line poem titled «فلسطين داري» (`فلسطين يا أرض الجدود…`, `بلادي بلادي…`, `يا شعب قم…`) is matched as pack «فلسطين» with map `[0,1,5,6,7]`. It gets that pack's verse meanings, tale, pictures, and `age` overwritten to the pack's age (line 394).
- **Fix:** Use the title only as a tie-breaker. Require ≥60-75% *aligned* hits regardless of title, plus a minimum score per matched verse (two keys where the pack lists two). Also show the parent «تعرّفنا على: …» with an undo, rather than applying the pack silently.

## MEDIUM

### M1. A child can start «ردّد بعدي» while recording: the model's voice goes into the take, and a second mic opens.
- **Evidence:** `karaoke()` line 1009 returns `echoYoung(r)` for age ≤7 *before* the recording guard on line 1010. `echoYoung` (978-998) has no `rec.state` check. It plays the parent's model through the speaker and calls `sessionRecorder()`, which is a second `getUserMedia`.
- **Impact:** The model's audio is recorded into a level-4 take captured as `recLvl=4`, so `memOk` can be true and the take is queued as «🧠 غيباً». Also, `level` is mutated mid-take. The non-marked `modelBtn` → `playRecSheet` path (line 868) has the same problem.
- **Fix:** Put the `if(rec&&rec.state==='recording') return toast(...)` guard at the top of `karaoke`, `echoYoung` and `playRecSheet`, or hide `#modelBtn/#echoBtn/#theaterBtn` while `.rec.live`.

### M2. Reviews can be advanced on demand, not when due.
- **Evidence:** line 818: `isReview = memOk && (sw.mem||[]).includes(recSeg)` has no `reviewsDue` check. Every level-4 take of a memorised segment is labelled «🔁 مراجعة» in the parent queue, and «✓ ثابت» bumps `step+1` (line 1440).
- **Impact:** Four takes on day 1 plus four taps by the parent schedule the next review 60 days out. Spaced repetition is defeated, and the parent cannot tell, because every review looks due.
- **Fix:** Set `review` only when `reviewsDue(rp.id,who).includes(recSeg)`. Otherwise mark the take `practice:true`, and do not advance the schedule from it.

### M3. Child names that are `Object.prototype` members crash or corrupt state.
- **Evidence:** `okName` (line 339) blocks only `__proto__|constructor|prototype`. `pushNews` (line 482) does `(n[k] ||= []).push(...)` on a plain object. `ageSheet` (lines 434-435) does `Object.assign(kidInfo[name]||{}, …)`. `theater` uses `byWho[r.who]` (line 1035).
- **Repro (probe1.py, case 2):**
  - `pushNews('toString',…)` throws `n[k].push is not a function`. Every parent stamp for that child throws inside `stampEffects`, after `saveS()`.
  - `kidInfo['toString']=Object.assign(kidInfo['toString']||{}, {g:'g'})` mutates the built-in: `typeof Object.prototype.toString.g` goes from `undefined` to `string`.
- **Impact:** Unlikely with Arabic names, but it is a real crash path, and the code clearly tries to defend this boundary.
- **Fix:** Use `Object.create(null)` or `Map` for every name- or id-keyed dictionary (`S`, `kidInfo`, `news`, `albumSeen`, `wantModel`, `byWho`, `groups`, `BAYT`/`BW`/`LESSON`/`STORY` user-id entries). Or always read through `own()`. Alternatively, make `okName` reject `k in Object.prototype`.

### M4. Data-loss and recovery edges in backup/import.
1. **Truncated single-file backup:** A backup cut off mid-download is reported as «هذا ليس ملف نسخة احتياطية من «أنشودتي»» (probe1.py case 4, `trunc.json`), so the parent thinks they picked the wrong file. Fix: if `JSON.parse` fails but the text starts with `{"app":"anasheed"`, say "the file is damaged or incomplete, export it again".
2. **Imported age outside the UI range empties the home screen:** Import clamps age to 3-18 (line 1540) while the UI offers 5-12. A kid with imported age 18 gets `ageF='me'`, and the grid shows **0 cards** («لا شيء هنا») (probe1.py case 4). Fix: clamp to 5-12 (or treat >12 as 12) in import and in `ageOk`.
3. **Gender lost on import:** `kidInfo` is imported only when `num(v.age)` is truthy, so a 👧 set without an age is dropped. Fix: import `g` independently.
4. **Unknown fields persist:** `cleanRec` keeps every unknown field (`...r`) into both the `rec` and `meta` stores. A malformed backup can put arbitrarily large strings into `meta`, which is loaded in full on every `recMeta()` (home, parent page, story…). Fix: whitelist the fields.
5. **Memory peak on import:** Each part is read whole (`await f.text()`, `JSON.parse`, then a JS-loop `atob` into a `Uint8Array` per recording) at up to 60 MB per part (`__bkPart` default). That means ~3-4× peak memory on a low-end Android WebView. Fix: lower the part size to ~20 MB, and decode with `fetch('data:…;base64,'+b64).then(r=>r.blob())` or `Uint8Array.fromBase64` where available.
6. **One-tap deletes:**
   - «🗑 احذف الطفل المختار» (line 1462) deletes `S[pKid]` and `kidInfo` permanently behind a single `ask()`, with no undo and no automatic backup. The comment says "nothing of a deleted child is left for a new child of the same name to inherit", but all recordings are kept under the same `who` and are re-attached to a new child of that name (`loadLast`, archive, before/after).
   - Deleting a typed poem (line 1483) orphans its stats and recordings, and re-typing it creates a new id.
   - Fix: soft-delete (move to a `trash` key restorable for 30 days), or force a lite backup first.

### M5. The service worker re-downloads all 236 pictures (11 MB) on every release, and fetches immutable images network-first.
- **Evidence:** build.py:275-285. The cache name is `anasheed-{version}` with `version=1.0.<run_number>`, so every push to `main` is a new version. `install` does `addAll` of `img_files`, which are already content-hashed (`sha1[:12]`). `activate` deletes the old cache.
- **Impact:** For a family on Egyptian mobile data, each app update costs 11 MB plus the HTML. Every image is also fetched network-first, with up to a 3 s wait on a bad connection. In addition:
  - A failed image request falls back to `caches.match('index.html')`, which serves HTML as an image.
  - One failed image in `addAll` aborts the whole install, so the offline cache never updates.
- **Fix:**
  1. Keep a separate long-lived `anasheed-img` cache that is never deleted.
  2. Serve `img/*` cache-first.
  3. Precache only the images that are missing.
  4. Restrict the index.html fallback to navigation requests (`e.request.mode==='navigate'`).

### M6. Pack word meanings are not normalised like pack lines, and build.py does not validate them.
- **Evidence:** Lines are matched through `pnorm` (hamza forms, ة→ه, ى→ي), but `meanings[\`${p.id}|${w}\`]` is looked up by exact `wkey`. The authors work around this by hand-duplicating spellings, inconsistently.
- **Repro:**
  - probe2.py: `M('وسأفنى')` returns «وسأموت», but `M('وسأفني')` (Egyptian ي for ى) and `M('وسافني')` both return `null`.
  - A scan of packs.json (`review6/code`, inline script) found 18 keys with no normalised sibling, e.g. `هوى`, `دفئ`, `تئن`, `الطمأنينة`, `الأبدية`, `أسرى`, `الأسطر`.
  - It also found 4 keys that can never match, because they contain diacritics/shadda and `wkey()` strips those: `أفقأُ`, `الفلّ`, `المحتلّين`, `تدنّست`.
- **Fix:** In `applyPacks`, store pack words under `pnorm(w)`, and in `M()` fall back to `pnorm(k)` for `p.pack` poems. In build.py, assert `w == key(w)` for each `words` key.

### M7. Accessibility basics are missing for non-pointer and screen-reader use.
- **Evidence:**
  - The main record control is `<div class="rec" id="recBtn">` (line 298), with no `role`, `tabindex` or `aria-label`, so it cannot be reached by keyboard or switch access.
  - All filters and selectors are `<span class="chip" onclick>`: ages, poets, segments, memorisation levels, the kid chip, recFilter, pIndex. None is focusable or announced as a button.
  - Emoji-only buttons (`➜ 🎧 📊 ⬆ ⬇ ▶ 🗑 ⏹ 🔁`) rely on `title`, which TalkBack/VoiceOver on touch do not reliably announce.
  - Sheets (`#pop`) have no `role="dialog"`/`aria-modal`, no focus move or focus trap, and no Esc handling.
  - Picture-quiz options are `<button><img alt=""></button>`, which reads as an empty button.
- **Fix:** Make `#recBtn` a `<button aria-label="سجّل">`. Make chips buttons, or give them `role="button" tabindex="0"` plus Enter/Space handling. Add `aria-label`s, put `role="dialog" aria-modal="true"` on `.sheet`, and focus the first control on open.

## LOW

- **L1. A window can be locked mid-recording.** `lockTab()` (line 1560) covers the page (z-index 100 over the save sheet at 50) but does not stop an active `MediaRecorder`. `LS.set` then silently no-ops while `recPut` still writes. A take in progress in the older window can no longer be saved or judged. Fix: `stopRec()` and finish the save sheet before locking, or defer the lock until `!recBusy()`.
- **L2. Back navigation can stay blocked.** `recStarting` stays `true` while `getUserMedia` is pending (line 781), and `recBusy()` (line 552) then blocks ➜, 🎧, 📊 and Android back. Some browsers keep the promise pending while the permission prompt is ignored, which strands the child. Fix: add a timeout or a visible "cancel".
- **L3. A quiz's daily counted try is spent at start.** `beginCount()` stamps `qday[type]=today` when the quiz *starts* (line 1231), so a quiz abandoned by an accidental back tap uses up the day's counted attempt. Fix: stamp in `finishQuiz`.
- **L4. Duplicate quiz options.** In easy «أكمل البيت», distractors from other poems are not de-duplicated (line 1334), so two identical wrong options are possible with refrains.
- **L5. Typed-poem input is barely validated** (lines 1467-1474, 371-374):
  - A hemistich containing only U+200F (RLM) passes `trim()` (probe1: `["الأولى ‏","الثانية"]` accepted), and the poet can be an invisible RLM.
  - There is no limit on verse count: 500 lines produce 168 segment chips (probe3), and an imported poem with 600 verses is accepted.
  - The card placeholder uses `title[0]`, which shows half an emoji.
  - A pack match silently overwrites the age the parent chose (line 394).
- **L6. Child-facing imperatives are masculine-only in a few places**, despite `gw()`: the toasts at line 596 «أنشد المقطع…», line 624 «احفظ «…» غيباً», and «أوقف التسجيل أولاً» at lines 699/701/702/1010/1031. Line 913 «بانتظار أن يسمعك» is ungendered next to the gendered `يسمعكِ` branch.
- **L7. Kid icons repeat beyond 8 children.** There are only 8 icons (line 426); probe3 with 60 kids gives 8 distinct icons, so a non-reader cannot find their own icon.
- **L8. Blob URL leaks:** `certificate()` (line 1085) never revokes its URL. The parent-queue players push into `archURLs`, which is only revoked by `renderArchive`. In `renderStory`, the `IntersectionObserver` is never disconnected when the child leaves before the end.
- **L9. Unsafe script embedding in build.py.** `render()` (build.py:228-242) injects `json.dumps(...)` directly into `<script>` without escaping `</`. Any content string containing `</script>` or `<!--` breaks the page. Fix: `.replace('</','<\\/')` on each dump.
- **L10. build.py validation gaps:**
  - Pack `age` (2 ints, 5-12), `tale` (`title` str, `text` list of str), `lessons`/`acts` (list of str), `how`, `poet`, `first` are unchecked. A malformed `tale.text` throws at runtime on 📚 (line 882).
  - lessons.json values are not type-checked.
  - The silent fallback to Google Fonts when `fonts/` is missing means a CI install hiccup would ship a kids' app that calls fonts.googleapis.com. Fail when `CI=true`.
- **L11. No CSP at all.** Everything is inline, but a `<meta http-equiv="Content-Security-Policy" content="default-src 'self' data: blob:; script-src 'self' 'unsafe-inline'; connect-src 'self'; img-src 'self' data: blob:">` would stop exfiltration if an escaping bug ever lands. Electron and Capacitor would accept it as well.
- **L12. CI notes:**
  - Every push to `main` cuts a GitHub Release and a new APK `versionCode=run_number`. If the workflow is ever renamed or recreated, `run_number` restarts and Android refuses the update. Derive versionCode from a counter that cannot go back, such as commit count or a date.
  - `device-results` runs `if: always()` even when `android` failed, so it fails noisily on the missing artifact.
  - `pip install playwright==1.49.1` is version-pinned but not hash-pinned, and its transitive dependencies (`greenlet`, `pyee`) are unpinned.
  - The Gradle wrapper from `cap add` has no `distributionSha256Sum`.
  - `npm ci` in `electron/` runs install scripts. That is necessary for the electron download, and the job has no secrets, so it is acceptable, but worth noting.
  - The fonts step falls back to an unpinned `npm install` if the lockfile is missing; make that an error.
- **L13. Residual risk from the old public signing key.** `keys/anasheed.p12` with password `android` is still in git history (added and later deleted in `a6ec35e`). I found no other committed keys or passwords: I scanned every commit's file names and diffs, including the non-content JSON/YAML/py/js. The current workflow reads only `secrets.ANDROID_KEYSTORE`/`ANDROID_KEYSTORE_PASSWORD` and never echoes them. Two residual points:
  1. Make sure the Secret is a *new* key: add a CI step that compares `apksigner verify --print-certs` against a pinned SHA-256 fingerprint that is not the old key's.
  2. Any APK ever distributed under the old key can be "updated" by anyone with that key, who then gets the children's recordings. Those installs need uninstall and reinstall.
- **L14. Tests are timing-based.** The suites use 283 fixed `wait_for_timeout`/`sleep` calls, and the CI starts `http.server` followed by `sleep 1` with no readiness probe. They passed here, but they are a flakiness risk on slow runners. No test covers: an age change after memorisation (H1), greedy or typo pack alignment (H2), a title-only false positive (H3), echo during recording (M1), review taken when not due (M2), prototype-named kids (M3), a truncated single-file backup (M4.1), or the SW image cache across versions (M5).

## Checked and fine

- **XSS.** I swept with a hostile typed poem: `<img src=x onerror=…>` in the title, the poet, the hemistichs and the parent name, plus a kid name with HTML. I visited home, poem, sing, quiz menus, complete/order quizzes, parent page, archive and certificate. The handler fired **0** times (probe1.py case 3).
  - Every `innerHTML` sink I read uses `esc()`, `AR()` (which escapes), `textContent`, or values that are numeric or built in.
  - `hemi()` puts only Arabic-letter `wkey` output into attributes.
  - The lesson sheet (`lessonHTML`) escapes every pack field and every typed line.
  - The import report escapes `crash`.
- **Backup round trip.** It is covered by e2e_data and passes. Multi-part export is split by size, missing parts are detected by `backup` id and `part`/`last`, and recordings are de-duplicated on `who|poem|when`. `mergeStat` merges field by field and validates its ranges. `cleanRec` clamps lvl/seg/marks/stamp/type. Invalid base64 is counted as a failure rather than aborting (probe1 `badb64.json`). Odd `stats` shapes (null, strings, bad `rev`) merge without throwing.
- **IndexedDB.** Audio is stored as an ArrayBuffer (Safari private mode); `arrayBuffer()` is awaited *before* the transaction opens, so there is no auto-commit bug. The rec/meta split keeps lists cheap. The v1→v2 upgrade copies meta, and there is one open request with a timeout plus a reconnect-and-retry on a dead connection. A failed save keeps the take and offers 📤.
- **Recording races.** A double tap is guarded by `recStarting`/`recStopping`. A recording is discarded if the child left during the permission prompt (line 785). Each recorder has its own chunks and `myT0`. There is an auto-stop cap. The modal save sheet can only be dismissed through «احفظ»/«امسح», with 8 s undo. The wake lock is released.
- **Prototype pollution from backups and poem ids.** It is blocked by `okKey`/`okName`/`own()`. I tested an imported `added` entry with id `__proto__`, and it was rejected.
- **Signing and secrets in CI.** Signing comes only from `secrets.*`; the job warns if the key is placed in Variables. The keystore goes to `$RUNNER_TEMP`, and the password is read through `System.getenv` in Gradle, never written to a file. Workflows default to `contents: read`, and only the publishing jobs get `write`. Every third-party action is pinned by commit SHA, and `persist-credentials: false` is set everywhere. npm uses lockfiles with `--ignore-scripts` wherever scripts are not needed, and font CSS is filtered to `@font-face` rules with data: URLs only.
- **Electron.** `contextIsolation` and `sandbox` are on. Navigation and new windows are denied or sent outside the app, permissions are allow-listed, and the app is single-instance.
- **Performance.** With a 500-verse typed poem and 60 kids: save 39 ms, home render 1 ms, open poem 3 ms, starting a whole-poem quiz 6 ms, and 21 KB of localStorage (probe3). `www/index.html` is 498 KB: ~170 KB code, with PACKS 99 KB, BW 71 KB, POEMS 65 KB and meanings 40 KB as the largest data blocks. Pictures are *not* inlined in `www/` (236 separate files); only `dist/` (15.3 MB, Windows and the release preview) inlines them.
- **Review scheduling arithmetic.** It uses local-midnight `dueIn` and `localDay()`, and steps are clamped to `REVIEW_DAYS`. A parent stamp is required for 🧠, and `rpend`/`pend` keep pending takes out of the "due" list.
- **Quiz scoring.** ⭐ needs two distinct types at ≥80%, counting only the first try per type per day. Trivial picture questions and easy «أكمل البيت» are excluded from the count, and a minimum of 3 counted questions is enforced. The order quiz never shows a pre-sorted shuffle.

## Score: 6.5 / 10

The code is defensive in a way that is rare for a one-person app. Inputs from storage and backups are validated, keys are prototype-guarded, IndexedDB handles WebView quirks, recording races are thought through, the CI supply chain is SHA-pinned with least-privilege tokens, and escaping is consistent enough that a deliberate XSS sweep found nothing. A real e2e suite also passes. Two things hold the score back.

1. **Core data model.** Progress is stored as indices into an age-dependent segmentation (H1). This produces false 🧠 badges and certificates on a child's birthday. Review and stamp semantics also allow early advancement (M2).
2. **Pack feature heuristics.** The flagship pack feature uses a greedy, title-boosted heuristic (H2, H3) that can show children confidently wrong meanings.

Maintainability is also weak. One 177 KB HTML file holds dense 400-850-character lines and dozens of module-level mutable globals (`cur`, `seg`, `segs`, `mode`, `level`, `rec`, `qs`…) mutated from async callbacks. Correctness therefore rests on careful `cur!==p0` checks scattered by hand. Those checks are present in most places, but they are easy to miss (M1), and the timing-based tests (L14) would not catch such misses.
